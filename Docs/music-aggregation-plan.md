与方案不同或补充的决定：

- QQ 关键词搜索使用 `DoSearchForQQMusicMobile`（`ct=11`）并附随机 `searchid`；桌面方法匿名返回 2001。连续搜索后移动方法仍会间歇返回 2001，此时以网易结果为准，界面提示。
- 网易目录经 GD 搜索，时长与封面另取网易 `api/song/detail`（一次请求，不占 GD 配额）。没有时长就无法判断试听，也无法与 QQ 按时长归并。
- FLAC 实际格式由本地解析 STREAMINFO 得到（采样率、位深、总采样数→时长），其余格式用 AVFoundation 补充。两家 CDN 对 FLAC 分别返回 `audio/x-ogg` 与 `audio/mpeg`，印证 Content-Type 不可作为证据。
- 未命名的“…版”、语言版本（粤语版、国语版）、“治愈版”等记为“其他版本”，不与原版归并。
- 直达：查询点名歌名（必要时加歌手）且版本一致；同一歌手同名条目按时长分组，原版所在组须多于任何其他组（合辑重复原版，单个未标记的 remix 不阻止直达）。
- 同一目录内 VKeys 与 HYW 不并行；只有两个目录的首选渠道可并行，冷却中的渠道单独排在最后。
- QQ 独有歌曲所有渠道失败时，按“歌名 + 首位歌手”在网易查一次同一录音（须通过 `sameRecording`），再试 GD。
- HYW 的 Key 不写入仓库或日志，由用户在“音乐设置”填写；未填写时 HYW 关闭。
- iPhone 标签栏放“音乐”，“来源”移入“更多”。
- 按用户要求提前实现原定后续阶段的内容：专辑与歌单搜索（QQ `search_type` 2/3、网易 `api/search/get/web` type 10/1000，均不占 GD 配额）、专辑与歌单曲目（最多 500 首）、播放队列（上一首/下一首、播完自动下一首、无法播放自动跳过但连续 3 首失败即停）、同步歌词与翻译（优先取正在播放录音所在曲库）、播放历史与“继续播放”（重启后仍可从上次位置继续）。后台播放与锁屏控制仍未做。

在线样本（2026-10-13，Mac，`MusicLiveTests`）：晴天 FLAC 24-bit/44.1 kHz 269.75 秒（VKeys）；稻香 16-bit 223.45 秒（VKeys）；七里香 16-bit 299.20 秒（VKeys）；江南 16-bit 267.95 秒（VKeys 风控→GD）；十年 205.42 秒、Love Story 236.27 秒（GD）。六首均为直达。另一次运行中 VKeys 对稻香超时（8 秒），HYW 未配置，按预期报告超时。Mac 应用实测：晴天 VKeys 24-bit 出声约 0.2 秒；宝可梦相关曲目经 GD 出现 24-bit/192 kHz FLAC。

## 1. 目标与范围

用户输入歌曲名，必要时加上歌手，映匣找到正确歌曲，选择当前可用且符合音质偏好的渠道并播放。渠道故障时自动尝试同一录音版本的其他地址。

第一版支持 macOS、iOS 和 tvOS，默认采用“无损优先，允许降级”。曲库目录和播放解析分别适配，通过应用内的原生网络请求工作，不要求用户部署服务、安装脚本运行环境或填写个人音乐平台账号。

“最好”定义为：在已接入渠道、当前请求预算和设备播放能力内，优先版本正确、完整可播、音质满足要求，再考虑稳定性与加载速度。默认模式不承诺遍历全网或找出最高位深的每一种版本。

第一版不做离线下载、全曲库爬取、音频转码、歌词同步、推荐算法或服务器音频代理。后台播放、锁屏控制、连续歌单播放作为后续独立阶段；前台搜索和单曲播放先闭环。

2026-10-13 的公开接口测试没有提供个人音乐账号或支付费用。共取得 11 首不同歌曲的 FLAC 地址并读取了格式、时长等信息；这只是小样本，不能推导全曲库覆盖率或长期可用性。

## 4. 数据与适配器边界

目录供应商与音频解析供应商分别实现协议，允许替换其中一个而不改变整个流程。

| 模型 | 必要内容 |
| --- | --- |
| `MusicTrack` | 本地 ID、标题、歌手列表、专辑、版本标记、预期时长、封面、各平台 ID、匹配证据 |
| `MusicCandidate` | 目录平台、解析供应商、曲目 ID、目标音质、已知上游依赖 |
| `ResolvedMusicStream` | 临时 URL、必要请求头、供应商宣称音质、解析时间、已知有效期；未知有效期保持未知 |
| `MusicProbeResult` | 真实编码、采样率、位深、时长、设备可播状态、验证时间、验证依据与未确定字段 |
| `MusicPlaybackSelection` | 选中歌曲与候选、选择原因、实际音质、是否降级、剩余备用候选 |
| `MusicProviderError` | 无匹配、无资源、试听、限流、上游风控、认证要求、超时、无效响应、格式不支持、用户取消 |

保留 `claimedQuality` 与 `observedQuality` 的差别。资料缺失用未知值，不推断为高音质或完整版本。URL 与请求头只在解析及播放层流转，诊断日志不记录签名参数、Cookie 或 Key。

## 5. 搜索、匹配和选择规则

### 5.1 搜索与歌曲身份

1. 用户提交查询后，并行查询 QQ 和 GD / netease 元数据。输入防抖、取消和缓存都在解析播放地址之前完成。
2. 统一空白、Unicode 形式及大小写，但保留 Live、伴奏、翻唱、Remix、重录等有意义的版本标记。
3. 平台内以歌曲 ID 去重。跨平台综合歌手、标题、版本、专辑与时长判断；同名或时长相近本身不足以证明是同一录音。
4. 默认优先原唱录音室版本；用户明确指定现场或重录版时保留该要求。不能把 Taylor's Version 与原版等不同录音自动合并。
5. 唯一高置信度结果可直接进入解析；仅有歌名且同名作品较多时显示候选供选择，不擅自播放第一首。
6. QQ 搜索空结果不记作全平台故障。已知歌手时可查缓存或有限分页目录；不能由歌名猜测歌手 MID，也不能扫描整个曲库补救。

### 5.2 默认选择策略

以“无损优先，允许降级”为默认，另提供“仅无损”。第一版不增加容易被误解为全网最优的最高音质模式。

1. 先通过歌曲身份检查，再请求目标歌曲的播放候选。QQ 首选 VKeys，网易首选 GD；跨平台已有高置信度匹配时可最多并行两个候选。
2. 对已经验证的结果按完整性、设备可播性、音质类别、健康记录和延迟排序。无损优于有损；不同有损编码不能只比较码率数字。
3. 第一个满足目标的正确、完整且设备可播的无损候选即可开始播放，并取消不再需要的请求。默认不为未知的更高位深持续等待。
4. 暂时只有有损候选时，继续在剩余预算内尝试无损来源；预算耗尽后，允许降级模式选择可播结果并标注，仅无损模式返回清晰失败原因。
5. QQ 主路径失败时尝试 HYW；单次请求内同一路径只尝试一次，地址过期刷新除外。识别相同上游依赖，避免重复请求同一服务。

24-bit、较高采样率或 FLAC 封装本身不能证明原始母带质量，也不能排除有损转制。界面展示已验证的格式，不使用“真母带”等无法证明的描述。

### 5.3 验证与平台播放

- 解析成功至少要求业务状态正确、URL 有效；HTTP 200 或非空字符串不是充分条件。
- 用受限的 Range 读取、必要的格式头解析和 AVFoundation 检查取得音频信息。不能将扩展名或 Content-Type 当作实际编码证据。
- 音频时长与已匹配版本的预期时长比较；明显缩短的 30/60 秒片段判为试听。初始完整性容差可设为 `max(3 秒, 预期时长 × 2%)`，作为待样本校准的参数，而非跨版本合并依据。
- 短歌不能仅因少于 60 秒被拒绝。预期或实际时长未知时继续补充信息；预算内无法确定则保持“完整性未确认”，不静默宣称完整。
- Range 被忽略时按实际接收字节中止探测，不因服务返回 200 下载整个文件。禁止为验证音质默认整曲下载。
- `ffprobe` 结果仅作为开发调研证据，不成为 iPhone / Apple TV 运行依赖。第一阶段必须验证原生远程 FLAC 解码、首段播放和跳转。
- VKeys 样本中有 HTTP 音频 URL。检查三端实际网络策略、重定向和 CDN 请求头；不假设将 URL 改成 HTTPS 必然可用，不关闭证书校验来掩盖错误。

## 6. 请求预算、缓存与故障切换

以下为初始工程参数，实施后根据实测调整，不是已测性能承诺。

| 项目 | 初始策略 |
| --- | --- |
| 搜索 | 防抖 350 ms，最多两个目录请求并行，单源超时 6 秒；先展示已有结果 |
| 地址解析 | 全局最多两个请求并行；单路径超时 8 秒；单次选歌解析与探测总预算 15 秒 |
| 音频探测 | 单候选最多 3 秒、应用主动探测最多接收 256 KiB；不足以确认时保留未知状态 |
| 播放起步 | AVPlayer 加载另设 10 秒故障观察窗口；分别测量解析耗时与开始出声耗时 |
| GD 限流 | 统一计算搜索、解析及其他 API 请求；本机滚动 5 分钟不超过 50 次，遵守服务端 429 / Retry-After，多设备仍可能共享上游配额 |
| 缓存 | 搜索短缓存建议 10 分钟，曲目资料 24 小时；播放 URL 只做当前会话复用，已知到期提前失效，未知则下次播放重新解析 |
| 临时错误 | 指数退避并加入抖动；遵守上游冷却提示。风控不通过密集重试解决 |

健康记录按“供应商＋平台＋操作”保存，目录成功不能清除播放故障。用户取消、本机离线和单曲缺失不触发整个平台熔断。冷却结束后允许有限试探请求。

播放会话使用独立代次标记。用户换歌或停止后取消旧搜索、解析与探测；迟到的响应不能替换新歌。

播放中地址失效时，先对当前候选重新解析一次，再切换到未尝试的备用。单次恢复最多两次解析尝试，失败后显示重试入口，避免无限循环。只有确认同一录音版本且可定位时才按已播放时间续播；版本不同则让用户选择，不静默替换。暂停、系统音频中断和暂时缓冲不直接等同于源失效。

## 7. 用户界面

- 音乐入口包含搜索框、歌曲列表和播放器；列表展示歌曲名、歌手、专辑或版本。
- 默认无需选择渠道。播放器展示实际格式，例如 `FLAC · 16-bit / 44.1 kHz`，未确定时显示“音质待确认”。
- 允许展开“播放渠道”查看当前来源并手动切换；技术错误详情放在诊断中。
- 降级时显示“当前使用有损音质”；仅无损模式失败时提示“暂未找到可用无损版本”。
- 区分“没有匹配歌曲”“找到歌曲但暂无可用渠道”和“网络连接失败”。
- tvOS 验证遥控器焦点、返回、播放暂停与进度操作；文案接入现有本地化资源。

## 9. 验证方式

规则与故障测试使用本地固定响应和自生成短音频，不依赖随时变化的公网接口，也不把完整商业歌曲提交到仓库。在线样本检查作为独立、低频、可手动运行的集成验证，不接入每次 CI。

必须覆盖：试听识别、短歌、缺失时长、格式误标、Range 被忽略、限流窗口、Retry-After、超时、取消、换歌竞态、地址过期、供应商熔断、相同录音续播以及不同版本拒绝续播。

音乐音频质量应分别记录“供应商声明”“头信息确认”“平台解码成功”，不能用接口返回码替代后两项。真实母带来源和有损转制不在本方案自动验证能力内。

## 10. 接口参考与使用限制

### VKeys 新版

```text
GET https://api.vkeys.cn/music/tencent/song/link?mid=003aAYrm3GE0Ac&quality=10
成功：code == 0；播放地址：data.url
```

本轮实际测试 `quality=10`。公开适配代码还将 `8` 定义为 HQ、`11` 定义为 HiRes，但不应把未测试档位视为已验证可用。

参考：[musicdl QQ 适配](https://github.com/CharlesPikachu/musicdl/blob/master/musicdl/modules/sources/qq.py)、[音质映射](https://github.com/CharlesPikachu/musicdl/blob/master/musicdl/modules/utils/qqutils.py)。实现时固定所参考的提交版本，避免后续上游变动造成歧义。

### GD Studio

```text
GET https://music-api.gdstudio.xyz/api.php?types=search&source=netease&name=林俊杰江南&count=5&pages=1
GET https://music-api.gdstudio.xyz/api.php?types=url&source=netease&id=108914&br=999
播放地址：url；查询参数通过 URLComponents 编码
```

采用标准浏览器 User-Agent，本轮默认 Python UA 曾遇到拒绝。`740` 和 `999` 是请求档位，不能直接用于界面标记实际位深。

[服务文档](https://music-api.gdstudio.xyz/api.php)在调研时声明每 5 分钟最多 50 次请求，要求注明“GD音乐台(music.gdstudio.xyz)”，限定个人学习参考并禁止下载、传播或商用。开发验证与公开产品发布分别判断适用范围；公开接入前需解决使用条件，不把当前免费调用视为音乐分发授权。

### HYW

参考 [V261008 发布包](https://github.com/guoyue2010/lxmusic-/releases/tag/V261008)中的 `HYWmusic_公益版V1.2.0.js`。本轮协议为：

```text
GET https://103.79.184.97/api/music/url
参数：platform=tx、source=tx、songId=<QQ MID>、quality=flac、key=<供应商公开配置>
播放地址：url
```

公开配置可能变化，具体使用条件需随版本核对；不在文档或日志复制 Key，不运行未经检查的远程脚本。保留标准 TLS 校验，解析失败按供应商错误处理。

### QQ 歌手目录示例

POST https://u.y.qq.com/cgi-bin/musicu.fcg
Content-Type: application/json

{

读取 `req_1.data.songList[].songInfo`。这是本轮测试成功的歌手目录请求，不是稳定公开 SDK 的保证，也不是关键词搜索接口。实现阶段需单独解决关键词搜索稳定性，不能以固定歌手示例替代搜索功能验收。
